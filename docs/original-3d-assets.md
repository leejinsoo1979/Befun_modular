# Original configurator runtime and 3D asset mirror

Inspected the public reference on 2026-10-15. The previous independently drawn furniture scene does not reproduce the original mesh/material/UI fidelity. The files recorded here are the **actual publicly served configurator runtime and scene**, downloaded read-only, for the requested local mirror.

## Actual loading URLs

The public HTML at <https://flexcube.ch/en/pages/konfigurator> names these files:

| File | Public source URL | Local path |
|---|---|---|
| UI and configurator logic | <https://flexcube.ch/cdn/shop/t/5/assets/configurator.js?v=59525409401430670271791791437> | `/original-configurator/configurator.js` |
| Verge3D engine | <https://flexcube.ch/cdn/shop/t/5/assets/v3d.js?v=160173461860661030221767690361> | `/original-configurator/v3d.js` |
| Original glTF scene | <https://flexcube.ch/cdn/shop/t/5/assets/configurator-scene.json?v=62752250576742739911791384326> | `/original-configurator/configurator-scene.json` |

The engine identifies itself as **Verge3D 4.1.1**. The scene identifies itself as **glTF 2.0 generated by Soft8Soft Verge3D for Blender add-on**. The main bundle is 3,436,173 bytes, engine is 1,495,628 bytes, and scene is 2,623,503 bytes. These three local files retain their downloaded bytes without changes.

`public/original-configurator/manifest.json` records every downloaded original URL, relative file path, byte count, and SHA-256 checksum. It also records template thumbnail and public template JSON sources. The main application bundle includes its UI CSS, Vue runtime/components, icons/images, option data, catalog data, and much of its export stack. It is not merely a 3D scene.

## The scene is self-contained

The scene contains:

- 48 meshes, 104 nodes, 27 materials, 3 textures, 1 camera, and 313 accessors.
- One geometry buffer with decoded length **1,347,324 bytes**, embedded as a `data:application/octet-stream;base64,...` URI.
- Two JPEG images embedded as `data:image/jpeg;base64,...`.
- One HDR environment embedded as `data:image/vnd.radiance;base64,...`.
- **Zero external image or buffer URIs**. No additional `.bin`, `.glb`, texture, or HDR network file is needed to reconstruct this downloaded scene.

The scene's custom extensions are `S8S_v3d_texture`, `S8S_v3d_materials`, `S8S_v3d_camera`, `S8S_v3d_lights`, `S8S_v3d_mesh`, `S8S_v3d_node`, and `S8S_v3d_scene`. A generic Three.js glTF loader will not reproduce all of these extensions, node materials, environment processing, and original light/shadow behavior. For the requested original look, use the matching downloaded engine **and original application bundle together**.

Scene settings include automatic antialiasing, PMREM environment lighting, physically correct lights, maximum PMREM tile size 512, and PCFPOISSON shadows. The exported coordinate metadata is `Z_UP_RIGHT`; the engine handles the conversion. The original camera uses orbit controls, a 0.399596484 radian vertical field of view, 0.1/100 near/far clipping planes, target `[0, 0.869844735, 0]`, and exported position approximately `[3.371525, 4.958431, 3.353463]`. The application subsequently adjusts/fits its camera to furniture state.

## Actual mesh and material library

The source scene is a library of furniture part prototypes. The application clones, scales, connects, colors and animates these actual models for its module graph.

Representative node names include `frame_connector`, `frame_part`, `panel`, `legs`, `rollen`, `handle_ring`, `handle_default`, `handle_with_lock`, `flap_down`, `flap_top`, `metal_door`, `metal_door_two`, `glass_one`, `glass375`, `black_sides`, `fastening`, `drawer1_default`, `drawer1_75_default`, `drawer1_mech`, `drawer1_75__mech`, `shelf1`, `shelf2`, `hangers`, `prospekthalter40`, `prospekthalter75`, `materialschale1`, `materialschale2`, `schragablage1` through `schragablage8`, `background`, `transparent_shadow`, and selectable/annotation helpers.

Materials include `steel`, `grips_steel`, `drawer`, `glass`, `glass_door`, `accessory_material`, `key_material`, `rollen`, `hangers`, standard panel colors, RAL, and environment/transparent shadow materials. Replacing the original steel material with a generic metallic Three material is one reason an independent recreation looks different.

## Reproducing the original bootstrap

The original Shopify page follows this order:

1. Create an open shadow root on the `#app-container` host, append a child `<div id="app">`.
2. Set `window.FXC_SHADOW_ROOT` to that root and `window.FXC_MOUNT_TARGET` to that child.
3. Set `window.FXC_SHOPIFY_CONTEXT = {marketHandle:"ch", languageIsoCode:"en", customer:null}`.
4. Set `window.FXC_SCENE_URL` to the scene URL. For the local mirror, use `/original-configurator/configurator-scene.json`.
5. Load the matching `v3d.js` as a **classic script** so `window.v3d` exists.
6. Load `configurator.js` as a **module** after the engine is ready.

The main bundle starts by appending its complete UI stylesheet to `window.FXC_SHADOW_ROOT || document.head`. It mounts itself using `window.FXC_MOUNT_TARGET || "#app"` and creates a Verge3D application inside its own `v3d-container`. It then loads the URL supplied by `FXC_SCENE_URL`. Its fallback to the live original scene should not be relied upon when verifying the local mirror.

`host-original.css` is the public page's host/loader/font stylesheet extracted without edits. `host-local.css` contains the same CSS with only the four DM Sans font URLs redirected to their downloaded local equivalents. These font files are:

- `fonts/dm-sans-normal-latin.woff2`
- `fonts/dm-sans-normal-latin-ext.woff2`
- `fonts/dm-sans-italic-latin.woff2`
- `fonts/dm-sans-italic-latin-ext.woff2`

The host uses DM Sans, background `#f1f1f2`, black text, no border/padding/margin, and width `100vw`. The original page's loader disappears after successful application import; scene initialization continues asynchronously.

## Public template and thumbnail mirrors

The 54 explicitly public gallery configurations are mirrored as `configurations/<id>.json`, preserving the actual GET response shape `{configuration:{id,price,articles,data,...}}`. Each of their 400px and 800px gallery thumbnail variants is mirrored under `templates/<template-id>-1x.<ext>` and `...-2x.<ext>`. Manifest mappings retain the original URLs. The unmodified runtime's literals still point to original public thumbnail URLs; a local wrapper or a separately named localized runtime may redirect those image references if fully offline operation is required. Do not claim the unmodified runtime has no remote image requests.

## Service boundary and verification status

The original runtime contains save/account/product-creation/cart service calls. These are separate from rendering and editing. Before exercising the local mirror, the integration wrapper should keep those calls local or block them, so original-store user/account/product/cart mutations cannot be sent accidentally. Read-only template GETs can be served from the mirrored JSON responses. This research performed only public GET downloads; it did not log in, save a user configuration, create a Shopify product, add to a live cart, or place an order.

Confirmed by this research: actual source URLs, successful public downloads, unmodified runtime/engine/scene bytes, scene structure and embedded resources, prototype/material names, font and template mirrors, original bootstrap pipeline, and the ability to assemble all required rendering files locally. **Successful local browser execution, original-versus-local screenshot parity, pointer behavior, GPU rendering, and export behavior must still be verified by the root task.** Merely downloading these files is not proof of a completed visual clone.
